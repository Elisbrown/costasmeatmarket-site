# SEO playbook: full reference

Every step taken on costasmeatmarket.com (a butcher shop and Brazilian/Latin market in Davenport, FL, with
the site in English, Spanish and Portuguese), written as repeatable steps. "Reference repo" means
`elisbrown/costasmeatmarket-site`. Section numbers match the phases in `SKILL.md`.

---

## 0. Inputs to collect before starting

| Ask for | Why |
|---|---|
| Search Console **Performance export** (zip: Queries, Pages, Countries, Devices; last 3 months) | Real keywords, position, CTR, old URLs still getting impressions |
| Microsoft Clarity dashboard export (CSV) or GA4 access | Devices, browsers, outbound taps, AI-assistant referrals, INP |
| Google Business Profile screenshot | Rating, review count, hours, categories, the "complete your profile" items |
| Full-size real photos (storefront, counter, products, team, dishes) and the logo as PNG | Heroes, galleries, share cards. Thumbnails under ~600 px are unusable |
| Confirmed facts: hours, products and services offered, staff languages, payment methods, exact address and phone | Content and schema may only state confirmed facts |

| The old platform (Shopify, Wix, WordPress) and its URL patterns | Redirect map |
| GA4 measurement ID and Clarity project ID | Tracking snippets |

- No browser, so Claude can't log into Search Console, Business Profile or social apps. Use Claude in Chrome

- There's no keyword-volume tool unless one is connected. Search Console data is the primary source.

## 1. Keyword research from real data

1. **Queries report**, sorted by impressions. Flag:
   - **Impressions with zero clicks at position 3–8.** This is a title or description problem, or there's no
     dedicated page. Example: "meat market haines city" had 36 impressions at position 4.7 and 0 clicks.
     Fix: a dedicated local article plus the town in the home titles.
   - **Position 8–20.** Quick wins: strengthen the existing page.
   - **Brand overlap noise** (e.g. "costa" alone: Costa Coffee). Ignore it.
   - **Product or service queries** (cuts, items). One article each.
   - **Queries in other languages** (pão de queijo, polvilho, carniceria, açougue). Justifies the language versions.
2. **Pages report:**
   - Old-platform URLs still getting impressions (about 40 Shopify `/products/...` pages). These go into the
     redirect map (§10).
   - The home page split between `www.` and the apex domain. Pick one host and redirect the other.
3. **Clarity or GA4:**
   - Device and browser split. 51% iPhone Safari meant Apple Business Connect was worth claiming.
   - Outbound tap rate, ChatGPT and other AI referrals, and INP (620 ms called for lighter pages).
4. **Keyword map:** a table with cluster, EN/ES/PT searches, target page and priority. Local "near me" and
   product clusters rank high. Back it with audience facts (e.g. tourists near Disney, about 200k Brazilians
   in Central Florida, 56% Hispanic in Osceola County).
5. **Search Console regex filters per cluster**, so the owner can track each one. For example:
   `picanha|picaña|top sirloin cap` and `a[cç]ougue|churrasco|quanto de carne`.
6. **Seasonal calendar:** articles to publish before the searches peak (holiday roasts by Nov 1, Nochebuena
   pernil by Nov 15, game-day wings by Jan 15).

## 2. Architecture

- **A static site generated by Python** (`_build/build.py`). Content lives in Python dicts, one file per
  topic per language: `_build/content/posts/<lang>/<topic>.py`. Topic order, category and photo are in
  `_build/content/meta.py`. The generated HTML is committed, and the host just serves files.
  - Why: fast pages, no framework, and an easy weekly rebuild in GitHub Actions.
- **URL plan:**
  - Home pages at `/`, `/es/` and `/pt/`.
  - Articles at `/blog/<slug>/`, `/es/blog/<slug-es>/` and `/pt/blog/<slug-pt>/`.
  - Slugs are keyword-based and localized, lowercase ASCII with hyphens, at most 60 characters, no dates.
    Example: `what-is-picanha` / `que-es-la-picanha...` / `picanha-nos-eua...`.
- **Link tokens in content:** `%%LINK:topic%%` (same language), `%%LINK:topic:pt%%`, `%%ORDER%%`, `%%TEL%%`,
  `%%MAPS%%`, `%%WA%%`, `%%SOCIALS%%`, `%%RECIPE%%`. The build fails on an unknown target or a leftover
  token, so internal links can't break.
- **Generated folders are wiped and rebuilt** each run. Images are cached separately (§7).
- Run `python3 _build/build.py`, then `python3 -m unittest test_seo_and_discovery`.

## 3. Multilingual

- `<html lang>` is `en`, `es` or `pt-BR`. JSON-LD `inLanguage` matches it.
- Every page has a self-referencing canonical, `hreflang` links for each language version plus `x-default`
  (English), and those links are reciprocal. It also has `og:locale` and `og:locale:alternate`.
- **Language switcher:** links with `hreflang` and `lang` attributes. `lang.js` remembers the choice
  (localStorage `cmm-lang`). If the phone's language differs from the page's, it shows a one-tap suggestion.
  It **never redirects**, so crawlers see every version.
- **Localize; don't just translate:**
  - Units in both systems (lb and kg, °F and °C).
  - Cut names by country (picaña or tapa de cuadril in Argentina, arrachera in Mexico).
  - Cultural framing: churrasco for Brazilians, parrillada or asado for Latin readers.
  - Separate keyword research per language.
  - Translate titles, descriptions, alt text, FAQs, schema text, share-card text and UI strings too.
- **Every article exists in every language.** A test enforces it.

## 4. On-page template

**`<head>` on every indexable page** (built by `head()` in `_build/lib/site.py`):

```html
<title>{keyword + place} | {Brand}</title>                 <!-- about 60 chars, brand last -->
<meta name="description" content="{120-160 chars: what, where, why}">
<meta name="robots" content="index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1">
<meta name="googlebot" ...> <meta name="bingbot" ...>
<meta name="referrer" content="strict-origin-when-cross-origin">
<link rel="canonical" href="https://site/path/">
<link rel="alternate" hreflang="en|es|pt|x-default" href="...">
<link rel="alternate" type="application/rss+xml" href="/blog/feed.xml">
<link rel="help" type="text/plain" href="/llms.txt" title="LLM and AI Agent Summary">
<link rel="sitemap" type="application/xml" href="/sitemap.xml">
<!-- Open Graph + Twitter (§6), fonts with preconnect and display=swap, CSS, icons + manifest -->
<script type="application/ld+json">{ "@context": "https://schema.org", "@graph": [...] }</script>
<!-- GA4 + Clarity + track.js + lang.js + search.js (§11, §15) -->
```

- **Home only:** a `keywords` meta tag, plus geo meta (`geo.region`, `geo.placename`, `geo.position`, `ICBM`,
  `format-detection`).
- **Article body, in order:**
  1. Language bar and search icon.
  2. Breadcrumb.
  3. Category chip.
  4. H1.
  5. Lede that answers the query directly.
  6. A byline line: author, published date, updated date (only when the content really changed), and
     reading time.
  7. Hero figure with a caption.
  8. A "In this article" contents list, when there are three or more H2s. Every H2 gets an id.
  9. The body: tables, lists, local facts.
  10. FAQ, as `<details>`, with three questions.
  11. Store CTA box: address, hours, order, call, directions, WhatsApp.
  12. Share row.
  13. Three related articles (same category first).
  14. Footer: address, phone, hours, socials, order, blog, RSS, sitemap, llms.txt, language links.
- **Home page visual hierarchy, top to bottom:**
  1. Logo.
  2. Eyebrow with the place.
  3. H1 with the brand.
  4. Tagline.
  5. Primary CTA card (order online).
  6. Quick-link tiles: socials, directions, call, blog, review, AI guide.
  7. Hours and location, with an open-now badge.
  8. Photo gallery.
  9. About.
  10. Visitor section (vacation rentals).
  11. Blog cards (one pinned plus weekly rotating).
  12. FAQ.
- **Blog index:** eyebrow, H1, tagline, search box, category chips, featured card that rotates weekly, a
  section per category, then the CTA.
- **Write `esc()` for HTML-escaping titles** with `html.escape(s, quote=False).replace('"', '&quot;')`.
  Plain `html.escape` turns apostrophes into `&#x27;`, which shows up in titles.

## 5. Structured data (JSON-LD `@graph`)

**The business node is the same on every page and referenced by `@id`** (`STORE_NODE` in `_build/lib/site.py`):

```json
{
  "@type": ["ButcherShop", "GroceryStore", "LocalBusiness"],
  "@id": "https://site/#store",
  "name": "...", "alternateName": [...], "description": "...", "url": "https://site/",
  "logo": "...", "image": ["..."], "telephone": "+1-...", "priceRange": "$$",
  "currenciesAccepted": "USD", "paymentAccepted": "...",
  "address": {"@type": "PostalAddress", "streetAddress": "...", "addressLocality": "...",
              "addressRegion": "FL", "postalCode": "...", "addressCountry": "US"},
  "geo": {"@type": "GeoCoordinates", "latitude": 0, "longitude": 0},
  "hasMap": "https://www.google.com/maps/dir/?api=1&destination=...",
  "openingHours": ["Mo-Sa 08:00-20:00", "Su 08:00-17:00"],
  "openingHoursSpecification": [{"@type": "OpeningHoursSpecification", "dayOfWeek": [...],
                                 "opens": "08:00", "closes": "20:00"}],
  "areaServed": ["Town, FL", ...], "knowsAbout": [...],
  "sameAs": ["facebook", "instagram", "tiktok", "online store"],
  "potentialAction": {"@type": "OrderAction", "target": {"@type": "EntryPoint", "urlTemplate": "..."}}
}
```

**Nodes per page type:**

| Page | Nodes |
|---|---|
| Home (each language) | Business node; `WebSite` with `SearchAction` (`urlTemplate` `.../search/?q={search_term_string}`, `query-input` `required name=search_term_string`); `WebPage` (`dateModified`, `primaryImageOfPage`); `ImageGallery`; `FAQPage` |
| Article | `BlogPosting` (`headline` ≤110 chars, `inLanguage`, `datePublished`, `dateModified`, `wordCount`, `articleSection`, `image` [share card + hero], `author` Organization, `publisher` `{"@id": "#store"}`, `isPartOf` Blog, `mainEntityOfPage`); `BreadcrumbList`; `FAQPage`; `Recipe` when there's a recipe; business node |
| Recipe | `name`, `description`, `inLanguage`, `image`, `author`, `datePublished`, `recipeYield`, `recipeCategory`, `recipeCuisine`, `keywords`, `recipeIngredient`, `recipeInstructions` (`HowToStep` with `position`), `prepTime`/`cookTime`/`totalTime` in ISO 8601 (`PT1H30M`). The visible recipe card is built from the same data |
| Blog index | `Blog` with a `blogPost` list, `BreadcrumbList`, business node |

**Rules:**
- **Schema states only what the page shows.** Hours, FAQs and recipe steps must all be visible on the page.
- **No `aggregateRating` for the business on its own site.** Google treats those as self-serving reviews.
  Stars come from the Business Profile. The site can say "100+ reviews on Google" in text.
- **FAQ markup still helps AI answers.** Google has shown FAQ rich results only for government and health
  sites since 2023, but AI assistants still read it. Google also removed Business Profile Q&A (announced
  December 2025) in favor of Ask Maps, which answers from the profile and the website, so on-site FAQs matter more.
- **`SearchAction` won't add a box in Google results.** Google retired the sitelinks search box in 2024; the
  markup still tells agents how to search the site.

## 6. Social share previews

- **One 1200×630 JPEG per article per language,** generated with Pillow (`og_card()` in `_build/lib/images.py`):
  - a real photo, cover-cropped, under a dark gradient;
  - the category label;
  - the title, wrapped, in the brand display font (Oswald, plus Karla for text);
  - the logo, and a footer with address and phone;
  - kept under 300 KB.
  - Cached by an input fingerprint so unchanged cards aren't re-rendered.
- **Tags:**
  - `og:type article`, `og:url`, `og:title`, `og:description`.
  - `og:image`, `og:image:secure_url`, `og:image:type`, `og:image:width`, `og:image:height`, `og:image:alt`.
  - `twitter:card summary_large_image`, `twitter:image`, `twitter:image:alt`.
  - `article:published_time`, `article:modified_time`, `article:section`, `article:publisher`.
- **Share buttons** for WhatsApp, Facebook, X and copy link. Every shared URL carries
  `?utm_source=<network>&utm_medium=social_share&utm_campaign=blog_<topic>`. On phones, copy link uses
  `navigator.share`.
- **Tests:** no two articles share a card; each card exists, is 1200×630 and is under 300 KB; `og:image` and
  `twitter:image` match.

## 7. Images and speed

- **Pages show WebP only**, and a test checks every `src` and `srcset`. Share cards stay JPEG, because every
  platform's link preview supports JPEG and pages never load them. Favicons stay ICO/PNG.
- `srcset` with 1200 and 640 widths plus `sizes`. Every image has `width` and `height`, which prevents layout shift.
- **Hero:** `fetchpriority="high"` plus `<link rel="preload" as="image">`. Every other image gets
  `loading="lazy" decoding="async"`.
- **File names are keyword slugs** (`fresh-ground-beef-carne-moida-costas-meat-market-1200.webp`). Alt text
  is localized and describes what's really in the photo.
- **Real photos only, never AI images.** With few photos, define crop variants (`VARIANTS` boxes in
  `images.py`) from the owner's full-size shots. Licensed stock (Pexels) is the fallback.
- **Search results get 120×120 square thumbnails** (a few KB each), not the 640 px card images.
- **Image manifest** (`_build/image-manifest.json`): a SHA-256 of each image's inputs. Rebuilds skip
  unchanged images, and outputs that are no longer used get deleted. Pin the Pillow version in CI
  (`pillow==12.3.0`) so the bytes stay identical.
- **Fonts:** `preconnect` to fonts.googleapis.com and fonts.gstatic.com, with `display=swap`.
- **Logo** exported as WebP at the sizes used. The socials page dropped from 81 KB to 35 KB.

## 8. Discovery files

**sitemap.xml:**
- Covers every indexable page and nothing else: no short links, search pages or 404.
- Each `<url>` has `xhtml:link` alternates for every language plus `x-default`.
- `image:image` entries for the hero images only.
- **`lastmod` must be honest.** Each article uses the date its source file last changed in git
  (`git log -1 --format=%cs`, or today if there are uncommitted edits). Home pages and blog indexes use the
  build date, because their featured content really rotates every week.
- A test checks that the sitemap lists exactly the indexable pages.

**robots.txt** (generated from `ROBOTS_TEMPLATE` in `_build/lib/discovery.py`):

```
# Last updated: YYYY-MM-DD (refreshed weekly with the sitemap)
User-agent: *
Allow: /
Disallow: /_build/

# AI search and assistant crawlers, allowed explicitly
User-agent: GPTBot / OAI-SearchBot / ChatGPT-User / ClaudeBot / Claude-SearchBot / Claude-User /
            anthropic-ai / PerplexityBot / Perplexity-User / Google-Extended / Googlebot / Googlebot-Image /
            Bingbot / Applebot / Applebot-Extended / Bytespider / CCBot / Diffbot / FacebookBot /
            facebookexternalhit / Meta-ExternalAgent / Twitterbot / WhatsApp / Amazonbot / cohere-ai
Allow: /          (one block per agent)

Sitemap: https://site/sitemap.xml
Sitemap: https://site/blog/feed.xml        (each language's RSS feed doubles as a sitemap)
LLMs: https://site/llms.txt
LLMs-Full: https://site/llms-full.txt
```

**llms.txt** (a short summary for AI assistants):
- Business details: address, phone, hours, rating with its date, areas served.
- Offerings and specialties, and how to save (coupons, WhatsApp group, discount for following).
- Key links: online store, socials, directions, site search URL pattern, sitemap, llms-full, robots.
- `Last updated:` the build date.
- "Featured This Week".
- The language home pages.
- **Every article URL**, with a one-line summary. A test checks every article is listed.

**llms-full.txt:** all the facts in one file: contact and location, hours, product categories, ordering
channels, service area, languages, common questions with answers, and every article with its category and
description, grouped by language.

**RSS:** one feed per language, linked from `<head>` and listed in robots.txt.

**Search Console:** submit the sitemap and the feeds (§12).

## 9. Honest freshness: a weekly GitHub Action

**What changes every week, for real:**
- Home pages and blog indexes rotate their featured articles. A `week_index()` built from the ISO week picks
  one pinned article plus three rotating ones.
- The "Last updated" dates in llms.txt, llms-full.txt and robots.txt.
- Sitemap `lastmod` for home pages and blog indexes.
- The RSS `lastBuildDate`.

**What doesn't change:** each article's `dateModified` and `lastmod`. They come from git history. Google uses
lastmod only when it's "consistently and verifiably accurate", and fake weekly dates teach it to ignore the
whole sitemap.

```yaml
name: Weekly content refresh
on:
  schedule:
    - cron: "17 9 * * 1"   # Mondays 09:17 UTC (off the hour, so the run isn't delayed)
  workflow_dispatch:
permissions:
  contents: write
concurrency: { group: weekly-refresh, cancel-in-progress: false }
jobs:
  refresh:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }          # full history, for each article's real date
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - run: pip install pillow==12.3.0
      - run: SITE_BUILD_DATE="$(TZ=America/New_York date +%F)" python3 _build/build.py
      - run: python3 -B -m unittest test_seo_and_discovery
      - run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add -A
          git diff --cached --quiet && exit 0
          git commit -m "Weekly refresh: rotate featured articles and update sitemap dates"
          git push
```

- The build reads the date from an environment variable (`COSTAS_BUILD_DATE` in the reference repo) and
  falls back to today.
- If `main` is protected, allow Actions to push, or the job fails at the last step.
- **Weekly is the right cadence for a small site.** Two improvements:
  - Also trigger on pushes that touch `_build/**`, so edits go live right away.
  - Drip-publish: write articles ahead with future `published` dates and have the build skip them until then.
    That gives real new content every week.

## 10. Migrating from an old platform: redirects

1. List the old URLs from the Search Console Pages report: products, collections, pages, account, cart,
   checkout, policies, blogs.
2. Map each old product or page URL to the closest new page, **in the same language** (`/es/products/x` goes
   to the Spanish article). Leftover old sections go to that language's home page (`OLD_PRODUCTS` and
   `OLD_SECTIONS` in `_build/content/redirects.py`).
3. Generate **every format**, so any host works:
   - `_redirects` for Netlify and Cloudflare Pages: `source  destination  301`, most specific first, with
     `/*` wildcards.
   - `vercel.json`: `redirects`, with `:path*` wildcards, plus the `www`-to-apex rule:
     `{"source": "/:path*", "has": [{"type": "host", "value": "www.site.com"}], "destination": "https://site.com/:path*", "permanent": true}`.
   - `404.html`: an inline script that looks up the path in the same map and calls `location.replace`. It
     sends a `page_not_found` GA4 event with the destination, and shows links in every language plus a search box.
4. **Old site search** (`/search?q=`) should land on the new site search, not a redirect.
5. **Test:** every redirect destination exists.
6. **One canonical host.** The owner sets the `www` redirect in the host's domain settings, then confirms it
   with URL Inspection.

## 11. Tracking and attribution

**GA4 in `<head>` of every page,** with a content group and the page language:

```html
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-XXXX', { content_group: 'blog/recipe', page_language: 'es' });
</script>
```

**Microsoft Clarity** is the standard snippet, also on every page.

**`track.js`** (deferred, about 8 KB):
- **Click events,** sent to both GA4 (beacon) and Clarity: `click_call`, `click_directions`,
  `click_order_online`, `click_whatsapp_group`, `click_whatsapp_channel`, `click_whatsapp_chat`,
  `click_google_review`, `click_instagram`, `click_tiktok`, `click_facebook`, `click_blog`,
  `click_socials_hub`, `select_language`, `share` (with method), and `search_*` (§15). Every event carries
  `link_id`, `link_url`, `link_section` (the nearest `data-section`) and `page_lang`.
- **Clarity `upgrade`** for the money actions (call, directions, order, WhatsApp group), so those sessions are recorded.
- **Source tags in Clarity:** UTM parameters; the referrer host classified as social (Instagram, Facebook,
  WhatsApp, TikTok, X, YouTube, Nextdoor), **AI assistant** (chatgpt.com, perplexity.ai, gemini.google.com,
  copilot.microsoft.com, claude.ai, meta.ai) or organic (Google, Bing, DuckDuckGo, Yahoo); first touch in
  localStorage and the session source in sessionStorage; and `traffic_source` as "source / medium".
- `window.cmmTrack(name, params)` for custom events.
- It injects gtag only if a page lacks it, as a safety net.

**UTM short links:** `/go/ig`, `/go/tt`, `/go/fb`, `/go/wa`, `/go/qr`, one per bio, QR code or partner.
- Each is a noindex page that fires `short_link_open` with a beacon and a callback, then calls `location.replace`.
- It has a 600 ms timeout and a meta-refresh fallback.
- Short links stay out of the sitemap.

**Tests:** GA4 and Clarity on every HTML file, and track.js on every indexable page.

**Owner's GA4 to-dos:**
- Mark the key events (call, directions, order, WhatsApp group, share).
- Add custom dimensions for `page_language`, `link_section`, `search_term`, `results_count` and `search_surface`.
- Link Search Console.
- Link Clarity to GA4.
- If the external store accepts a GA ID, set up cross-domain measurement.

## 12. Off-site local SEO (the owner does these, from exact written steps)

**Google Business Profile:**
- **Name exactly as the business is known, with no keywords.** Keyword-stuffed names get suspended.
- **Address and phone match the site character for character.**
- **Categories:** the primary category is the core business; add only secondary categories that are true.
- **Hours:** fill them in, plus holiday hours before each holiday.
- **Service areas:** the towns served.
- **Website field:** `/?utm_source=google&utm_medium=organic&utm_campaign=gbp`.
- **Order link:** the online store.
- **Products:** each with a photo, and the other-language names in the description so the profile matches
  searches in every language.
- **Services:** for example custom cuts, special orders, online ordering, bundles.
- **Description:** up to 750 characters, with the place, the specialties and the languages.
- **Photos:** 3–5 new ones a week, including the exterior.
- **Posts:** one or two a week, linked with `utm_campaign=gbp_post`.
- **Reviews:**
  - A QR code to the review link at the counter and on receipts.
  - Ask in person.
  - Reply within two days, in the reviewer's language.
  - **Never offer incentives.** Google prohibits incentivized reviews, and the FTC's 2024 consumer-review rule
    bans incentives conditioned on positive reviews. A discount for following on social media is fine; keep it
    separate from reviews.

**Other listings,** each with UTM-tagged website links:
- Apple Business Connect: `utm_source=apple`. Especially important when iPhone traffic is high.
- Bing Places: `utm_source=bing`. It can import from the Business Profile, and Bing feeds Copilot.
- Facebook page info, Yelp, Nextdoor Business.
- **Same name, address and phone everywhere.**

**Search Console:**
1. Add a Domain property (TXT record), or a URL-prefix property with a meta tag Claude can add.
2. Submit the sitemap and the feeds.
3. Request indexing for the home pages, blog indexes and the main articles.
4. Associate it with GA4.

**Monthly routine:**
- Export the queries and log each cluster.
- Act on the position 8–20 queries.
- Check Countries and Search appearance for the language versions.
- Keep a scorecard covering: Business Profile performance, Search Console by cluster, Clarity by
  `traffic_source` and `click_*` events, review count and rating, WhatsApp members, online orders, and GA4
  `search_no_results` terms.

**Hours everywhere, from one constant** (`HOURS` in `_build/lib/site.py`):
- Business schema, every page footer, the home hours table, the FAQs, llms.txt and the socials page.
- A live **open-now badge** computed in the store's time zone with `Intl.DateTimeFormat`
  (`timeZone: "America/New_York"`), showing "Open now · Closes at 8 pm" or "Closed now · Opens at 8 am".
- When hours change, update the constant and the Business Profile the same day.

## 13. Social profiles

**Bios** use the keyword, place and specialty, stay within the character limits, and link to a `/go/` link:
- Instagram name: 64 characters. Bio: 150.
- TikTok bio: 80.
- Facebook intro: 101, plus the category and the website field.

**Getting found inside the apps:** Instagram and TikTok index the speech, on-screen text and caption.
- Say the place and the product out loud.
- Put "Product in Town FL" in the on-screen text.
- Use 3–5 hashtags per post, mixing location and product, with sets per language.

**Content pillars:**
- Cut of the week, named in every language.
- "How much for your party?"
- Visitor weekends.
- Fresh arrivals and WhatsApp drops.
- Recipes.
- Behind the counter.

**Partnerships,** each with its own `/go/` link: vacation-rental managers (welcome-book flyers with a QR
code), community groups and churches, sports leagues.

**Scheduling tools (Buffer):**
- Check the account time zone first. It was Africa/Douala and needed to be America/New_York.

## 14. Content

**Topics come from the real queries.** The reference site has 28 topics in 3 languages, 84 articles, across
these categories:
- local guides: near a neighboring town, vacation rentals, groceries;
- cut guides: product explainer, cut-name translation, steak comparison, premium cuts;
- recipes: 12, with recipe cards;
- how-tos;
- basics: doneness chart, butcher vs. grocery store;
- party planning: per-person amounts, menus;
- deals and savings: coupons, cheap cuts, bundles, saving tips.

**Article recipe:**
1. A lede that answers the search directly.
2. 4–7 H2 sections.
3. At least one table (amounts, names, temperatures).
4. Local facts: address, area served, hours where relevant.
5. 2–4 internal links through tokens.
6. Three FAQ questions written like real searches.
7. The CTA box.
8. A recipe card when relevant.

**Promote subtly:** be genuinely useful, with the store as the natural place to buy ("ask the counter to cut
it 1½ inches thick", "order online and pick up on the way back from the parks").

**Accuracy:**
- Claim only verified stock and services. Uncertain items become "call to check" or "special order".
- Don't state staff languages unless confirmed. Wrong unverified claims were removed in review, for example
  "we speak Portuguese" and "fraldinha is stocked".
- Cite authorities for safety facts (USDA minimum temperatures, perishables out of the fridge for at most
  1 hour above 90 °F).

**Translations** should read as native, with regional names and both unit systems.

**Freshness:** the home page and blog index feature rotating articles, related posts are cross-linked, and a
seasonal calendar plans new articles (§1).

## 15. Instant site search

**Where it appears:**
- A search icon at the top right of every page. It opens an overlay, also with `/` or Ctrl+K.
- An inline search box with a dropdown on the blog indexes and the 404 page.
- Full results pages at `/search/`, `/es/search/` and `/pt/search/` with `?q=`. They are `noindex, follow`,
  kept out of the sitemap, and still carry GA4 and Clarity.

**Index (built at build time by `_build/lib/search.py`):**
- One JSON file per language (`/assets/search/<lang>.json`, about 33 KB gzipped).
- Loaded only when someone points at, focuses or taps a search control.
- Cache-busted with a content hash (`search.js?v=<hash>`; the script reads its own `?v=` through
  `document.currentScript`).

**Each language index has four groups:**
- **Products** (from `_build/content/search_terms.py`): names in all languages plus extra terms, each linking
  to its guide, with an Order button.
- **Recipes** and **Blog:** title, description, category, H2s with their anchors, FAQ questions, the bold and
  H3 text plus recipe ingredients, the other languages' titles and URLs, and the unique body words.
- **General:** hours, directions, call, order, coupons, WhatsApp, socials, reviews, custom cuts, home, blog,
  plus every home-page FAQ.
- **Synonym groups across languages** (`beef res carne boi`, `oxtail rabo rabada`) are expanded at build time.

**Ranking (in the browser, a few milliseconds per keystroke):**
- A vocabulary map from each token to (document, field).
- Per query token: an exact word scores 1; a word that starts with the token scores 0.6–0.97 (higher for the
  word still being typed); a typo scores about 0.5 (edit distance 1, or 2 for words of 8+ letters, adjacent
  swaps allowed); a substring scores 0.45.
- Typo matches are halved when real matches exist.
- Field weights: title 10, keywords 6, other-language title 5, synonyms 4, heading 4, FAQ 3.5, category 3,
  description 2.5, body 1.2.
- Every token must match. With three or more tokens, one may miss, at a penalty.
- Bonuses: the whole phrase at the start of the title (+8) or anywhere in it (+5); how much of the title the
  query covers; products that match on title.
- Results below 20% of the top score are dropped (10% on the full page).
- Matching ignores case and accents (NFD, combining marks stripped, apostrophes removed). The Python and JS
  normalization must match.

**Display:**
- Grouped by category, with the groups ordered by their best result.
- Matched prefixes highlighted.
- A match in an article section or FAQ links straight to `#anchor` and shows "Section: …".
- Products get an Order button.
- Keyboard: arrows to move, Enter to open (or go to the results page), Esc to close. A combobox/listbox with
  `aria-activedescendant`, and focus trapped in the overlay.

**Language awareness:**
- Distinctive words or characters (ç, ã, õ, ñ, ¿) reveal the query's language, and the results offer a link
  to the results in that language.
- If nothing matches, the other languages' indexes are searched too and shown with a language badge.
- On the results page, the language links keep `?q=`.

**Tracking:**
- GA4's recommended `search` event (`search_term`, `results_count`, `search_surface`, `page_lang`), sent once
  per term after 1.2 s idle, on Enter, or on a click.
- `search_no_results` for searches with nothing found. **This is the content to-do list.**
- `search_select` (`result_category`, `result_position`).
- A Clarity `search_term` tag and a `search_open` event.

**Redirects:** remove any old `/search` redirect, so old-platform `/search?q=` links open live results.

**Hand-built pages** (the socials page): the build rewrites their `search.js` and `search.css` version strings.

## 18. Gotchas met on this project

- `html.escape` turns `'` into `&#x27;`. Use `quote=False` and escape `"` yourself.
- Python f-strings that emit JS: double every `{` and `}`. Put conditional script tags in a variable rather
  than nesting quotes.
- `pkill -f "pattern"` can kill its own shell (exit 144). Use `pgrep -f "[p]attern"`. Start local servers
  with the Bash tool's background option, because `( … &)` dies with the shell.
- In a `.wrap ul` style, list padding overrode `.post-list`. Scope component styles explicitly.
- Building with a partial topic list fails on link tokens and the redirect map. Patch the topic list and
  redirects together in any test harness.
- Removing a redirect: also update the 404.html regex that mirrors it.
- A JS view that takes over an existing element must not overwrite its `id` (`if (!el.id) el.id = …`).
- Wrap-around arrow navigation over results plus the input: `((active + 1 + step) % slots + slots) % slots - 1`.
- `<mark>` defaults to a yellow background in dark mode. Style `mark` in every results container.
- The Clarity `upgrade` call and GA4 `transport_type: 'beacon'` make sure taps that leave the page are recorded.
- Stock sites and Canva can be blocked in cloud sessions. Plan to use the owner's photos.
